## 2. 定稿原则

### 2.1 建议是起点，不是终点

每条都要看上下文：谁对谁说、在什么场景、什么情绪、前后有没有回声或呼应。审查理由成立时，写出**这个人物会这么说**、读着自然的中文：

- **采纳**：建议译文已经合口吻，照用。
- **改写**：意思按审查理由改，措辞、语气词、语序按人物口吻调整（可以和建议不同，但不能偏离审查指出的问题，不加原文没有的信息，长度相近）。
- **不改**：审查理由不成立，或改了反而更差。写明原因，交维护者看。
- **联动**：为了衔接必须一起改、但不在清单里的行（回声问、整组换句时组内原本一致的行）。

### 2.3 常见问题怎么写

- **独白 / 自语的附加问句**（P9，约 166 条）：改成陈述或自言自语（「……呢」「……啊」「……吧」），不留「是吧？/不是吗？」；英文以 `?!` 收尾的保留「？！」，写成反诘（「她就不能让我省点心吗？！」）。「我总不能……吧？」这类惯用反诘本来就可以。
- **v8 口头禅**（约 89 条）：解释性 you see? → 句末「嘛 / 呢 / 啊」或句首「你看 / 您瞧」，真在确认对方听懂才用「明白吗？」；I wager / I'd say / I'm certain / that's for certain → 并入句中（八成、准是、我看、肯定、确实），不挂句尾「，我倒觉得 / 我得说 / 我估摸着」，年长者唠叨可少量「要我说」；that's what! → 强调句式或重复，「我就这么说！」可以；X, you say? →「你说X？/ 您是说……」；句尾 I suppose →「……吧 / 大概……」。
- **D5 标点**：原文没有省略号，不在「！/？」前加「……」；原文以 `...` 收尾，不加「！」；`...!` 保留「……！」；`?!` / `!?` 作「？！」。
- **Oh**：叹息「唉」、慌乱抱怨「哎呀」、长辈欢喜「哎哟」、轻蔑「哼」、孩子惊喜「哇」、招呼道谢想起来「啊」、疑惑「咦」，也可不译；「哦」只用于恍然、应答、轻声反问。
- **称谓**：同一场里同一对人物不要「您 / 你」来回换；单复数按受话人数；「咱们」只在包括听话人时用。
- **小偏差**：多为省略号、结巴、叠词、语气词照原文补回或删去，一般照用；同英文的整组（`Elise...!` 20 行、`What...?` 16 行、`Rosmarine...!` 13 行等）一起改。

### 2.4 硬约束（`round1_check.py` 会查）

- 标签（`<b> <i> <color> <sprite> <shake> <wave> <incr> <size>` 等）、`{0}` 占位符、换行与英文一致；备注写明有意偏离的行以现译为准。
- 全角标点；省略号「……」、破折号「——」都成对；引号「」，『』只用于引号内再套（及定案『赠礼』）。
- 名表、错叫名、术语照 `rules.md` §1–§3（萝森玛琳 / 萝丝玛琳不可互换；赠礼 / 信物 / 良伴 / 鲜嫩的血肉 / 最甜美的琼浆；女巫夜骑；节庆；星期X）。
- **显示层**：英文去标签后相同的行在游戏里只显示同一句中文。改了一行，同英文的所有行必须改成同一句（只允许标签不同）。冲突组按 `summary.md` §3 的定句；定句已经过两轮复核，原则上照用，只有确认某行人物口吻明显不合时才整组换句，组内原本一致的行用「联动」补齐。
- 锁定行不改：`SUB_001_*` / `SUB_002_*` 及同文 NARR、备注含「定稿·锁定」的行。

### 2.5 不改的（照 `summary.md` §7，写进 REPORT）

- 同键共用、没法分场景处理的：`Have a good day.`、`(This old hag...!)`、`Oh...`（8 行「哦……」）、`Is that so?`（8 行「是吗……」）。
- 风格选择，清单里没点名的不动：「日安」、town / village 的镇 / 村、old hag、lads、serpent、in the Lord's name、journal 的日记 / 日志。
- 源文疑误：清单里有建议的（`CHR_009_036`、`DLG_2_3_VSQ_03_021`），看上下文证据足够就改，备注写「源文修复」；`TASK_LUDWIG_CHICKENS` 不改（英文与 `TASK_LUDWIG_APPLES` 相同，改了会造成显示层冲突），交维护者游玩时核对。

## 4. 记录格式

### 4.1 决定文件 `review/round1/<批次号>.jsonl`

一行一条，键写进它所属批次（按 `manifest.csv`）的文件，全局每键只出现一次：

```json
{"key": "DLG_5_4_VSQ_01_025", "decision": "采纳", "final": "她是个出身寒微的丫头，威廉先生。", "note": "humble 指出身低微，非谦逊"}
```

- `decision`：采纳 / 改写 / 不改 / 联动。采纳时 `final` 等于建议译文；不改时 `final` 等于现译文。
- `note`：≤30 字，写进审查备注；不改的写不改的理由，联动的写因哪条联动。

### 4.2 写回 docs 时的列

`中文译文` = final；`修订状态` =「已修订」；`修订译文` = final（与现有已修订行一致，是中文译文的副本）；`审查备注` 末尾追加 `[全检·<级别><类别>] <note>`（联动写 `[全检·联动] <note>`；原备注非空用「; 」连接）。其余列不动。

### 4.3 `review/round1/PROGRESS.md` 模板

```markdown
# 修正轮进度
- 阶段：一（同键组）/ 二（逐批）/ 收尾
- 第一阶段：已定 X / 67 组
- 第二阶段：已完成批次 001–0xx；下一批：0xx
- 最近一次 round1_check.py：错误 0，提示 N
- 跨批联动待补：| 键 | 原因 |
- 交维护者（累积）：不改条目、源文疑误、需游玩确认的
```

## 5. 脚本（放 `review/scripts/`，复用 `lgts_common.py` 与 `validate_fixes.check_text`）

**`round1_show.py`**
- `round1_show.py <批次号>`：列出该批未定稿条目（跳过任何决定文件里已有的键）。每条打印级别、类别、冲突组、英文、现译、建议、理由、依据行，再按 manifest 顺序打印上下文（P0 / P1 / 衔接 / 分支 ±8 行，其余 ±4，小偏差里的标点格式 ±2），只印「键 | 英文 | 中文」，目标行标 `>>` 并附完整备注。
- `round1_show.py --groups` / `--group "<匹配键>"`：列出同键组（同 `norm(英文)` ≥2 行且至少一行在清单里），打印组内全部行（批次、键、现译、有无建议）和各行 ±3 上下文。
- 清单来自 `review/findings.csv` + `review/minor.csv`（列：严重度、记录键、批次号、类别、英文原文、现译文、建议译文、理由、依据行、显示层冲突组）。

**`round1_check.py`**（有错误退出码 1）
- 默认（接力中）：只校验已写的决定；未定稿条目按批次汇总成提示；同键组还有行没定稿时，一致性问题记「待补」提示。
- 错误项：①键存在、属于文件名的批次、全局唯一，decision 合法，final / note 非空、note ≤30 字；②采纳时 final = 建议译文，改写 / 联动时 final ≠ 现译文，不改时 final = 现译文，联动的键不在清单里；③docs 现译文 = 清单里的现译文（docs 没被别处改过）；④采纳 / 改写 / 联动的 final 过 `check_text(final, 英文, 现译, is_explained(行))`；⑤锁定行（`is_locked`）不能改；⑥把全部非「不改」的 final 叠到现译上，每个被触及的匹配键组内 `norm(中文)` 唯一，只差标签记提示。
- `--final`：1,036 条必须全部有决定，「待补」也算错误。
- `--post`（写回后）：逐条核对 docs 里采纳 / 改写 / 联动的行 中文译文 = final、修订状态 =「已修订」、修订译文 = final、备注含 `[全检`；不改的行没动；再全表扫描同 `norm(英文)` 而 `norm(中文)` 不一的组并列出。
- 输出：按决定、按级别的计数，错误与提示清单。

**`round1_apply.py`**
- 先做 `--final` 的全部检查，有错误拒绝写。
- 用 `lgts_common.load_rows()` 读、`lgts_common.write_csv(CSV_PATH, header, [[r[h] for h in header] for r in rows])` 写回（行是 OrderedDict，要按表头取值成列表；utf-8-sig、LF、QUOTE_MINIMAL，已验证不改内容时与原文件逐字节一致），行序、列序不变，只改 §4.2 的四列。
- 写后读回自检：只有预期的键变了，且只变了这四列；改动行数 = 采纳 + 改写 + 联动。`--dry-run` 只报告计数。
