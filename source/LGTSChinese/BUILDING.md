# LGTS 简体中文汉化插件 (LGTSChinese)

## 这是什么
BepInEx 插件, 通过 Harmony 后置钩子拦截游戏本地化取词
`I2.Loc.LocalizationManager.GetTranslation(...)`, 按 **RefKey** 精确返回中文。
这是"路线2 / 数据层注入", 相比"路线1 / XUnity.AutoTranslator 文本词典匹配"更稳:
- 富文本标签 `<color>`、变量占位由游戏原生流程处理, 零标签风险;
- 按 RefKey 匹配, 不受 I2/Gridly 两版英文异文影响;
- 不改 `data.unity3d`, 不触发完整性校验。

译文表 `translation/lgts_zh_by_refkey.json` 已按**游戏实际显示文本(Gridly 版)**对齐,
共 17,613 条 (详见 ../translation/realign_report.json 与 scripts/regen_translation_aligned.py)。

## 构建 (无需安装 .NET SDK)
本机只装了 .NET 运行时、无 SDK。改用系统自带的 Framework C# 编译器 (C# 5) 直接编译:

    双击运行  build.cmd     (或在本目录 cmd 执行 build.cmd)

产物: `build/LGTSChinese.dll`。
注: 源码已回退到 C# 5 语法 (无 nameof / 字符串内插), 以适配 in-box csc。
若日后装了 .NET SDK, 也可 `dotnet build -c Release` (见 LGTSChinese.csproj)。

## 部署结构
    <游戏>/BepInEx/plugins/LGTSChinese/
        LGTSChinese.dll
        translation/lgts_zh_by_refkey.json

改译文只需替换该 json 并重启游戏, 无需重编译。

## 与 AutoTranslator 并存 (当前采用)
本插件负责 **I2 数据层**文本 (对话/过场/事件等)。
同时保留 XUnity.AutoTranslator, 它负责两件本插件覆盖不到的事:
1. **CJK 字体回退** —— 已加载 `arialuni_sdf_u2019` 为 TMP 全局 fallback, 中文才不会显示成方块;
2. **非 I2 文本** —— 少量不走 I2 取词的 UGUI/TMP 文本, 由 AutoTranslator 的
   `Translation/zh/Text/_AutoGeneratedTranslations.txt` (同源同对齐, 21,563 条) 兜底。

两者互不冲突: 插件在 I2 层就把结果换成中文, AutoTranslator 在其英文词典里查不到中文,
自然跳过; 反之非 I2 的英文才由 AutoTranslator 处理。

因此本插件**不自带字体包**(font/lgts_cjk)。若要脱离 AutoTranslator 独立运行,
需在 Unity 2021.3.24f1 编辑器中用 P7/output/tmp_charset.txt 生成 SDF 字体 AssetBundle,
命名为 `lgts_cjk` 放到 `font/` 子目录 —— 插件会自动注入为 TMP fallback。
(切勿直接复制 arialuni_sdf_u2019 到 font/lgts_cjk: 与 AutoTranslator 同包会触发
 Unity "AssetBundle 已加载" 冲突。)

## 如何确认生效
启动游戏后看 `BepInEx/LogOutput.log`, 应出现:

    [Info :LGTS Simplified Chinese] 已挂钩 System.String GetTranslation(...)
    [Info :LGTS Simplified Chinese] LGTS 中文插件已加载, 词条 17613 条。

进对话后, 插件内部 Hits/Miss 计数递增 (Hits 为命中中文的取词次数)。
若日志报 "未找到 I2.Loc.LocalizationManager", 说明 I2 命名空间在本版本被裁剪/改名,
需按实际类型名调整 Plugin.cs 的 `AccessTools.TypeByName(...)`。
