# LGTS 简体中文汉化插件 (LGTSChinese)

## 这是什么
BepInEx 插件, 通过 Harmony 钩子拦截游戏本地化取词, 按 **RefKey** 精确返回中文。
这是"路线2 / 数据层注入", 相比"路线1 / XUnity.AutoTranslator 文本词典匹配"更稳:
- 富文本标签 `<color>`、变量占位由游戏原生流程处理, 零标签风险;
- 按 RefKey 匹配, 不受 I2/Gridly 两版英文异文影响;
- 不改 `data.unity3d`, 不触发完整性校验。

**取词路径（v1.3.32 查清, 与早先的理解不同）**: 本作对话/物品/过场**不走 I2**,
实际是 `StoryPath.Text`(即 RefKey) → `LocalizationMediator.GetTranslation(ref term)`
→ `Gridly.GridlyLocal.GetStringData(tab, recordID)`, `recordID` 就是译本记录键。
所以主路径是挂 `GridlyLocal.GetStringData` 的 postfix: 命中 `by_refkey` 返回该行专属译文,
未命中放行。I2 与 TMP 两个钩子是**兜底**, 覆盖 UI 短键、AT 漏翻、Timeline 旁白等
不带记录键的串。两条路径并存, 见 `tools/PIPELINE.md`「两条取词路径」。

四个数据载体 (口径必须分列统计, 禁用合并数字):

| 文件 | 键 | 用途 |
|---|---|---|
| `translation/lgts_zh_by_refkey.json` | 21,189 | RefKey → 中文, Gridly 精确取词主路径 |
| `translation/lgts_display.json` | 25,318 | Norm(去标签英文) → 中文, TMP/I2 兜底路径 |
| `translation/lgts_item_names.json` | 79 | 道具弹窗专用 (v1.3.18+), 79 条里含 16 条长描述, 缺失自动降级 |
| `Translation/zh/Text/_AutoGeneratedTranslations.txt` | 24,700 | XUAT 兜底层, 非权威 |
| `Translation/zh/Text/UI_System.txt` | 536 | 系统 UI 静态词典 (另有 9 行 `#` 注释) |

TMP 兜底钩子先查 display（**没有 by_refkey 兜底**；by_refkey 只服务 Gridly 精确路径），
再走模板/恋人弹窗规则，覆盖 Timeline 旁白等非 Gridly 正文文本。
三层词典如何从译本 CSV 同步生成, 见仓库根目录 `tools/PIPELINE.md`。

## 两个源文件的分工 (v1.3.33 起)

    Core.cs      零 Unity 依赖的译本引擎: Norm / ParseFlatJson / 六条模板规则 /
                 噪声判定 / 整句包色回包 / 道具复合弹窗。只 using System.*,
                 不得出现 UnityEngine / BepInEx / Harmony。
    Plugin.cs    Unity 接线层: Harmony 钩子、组件路径判定、DIAG 落盘、字体通道。

这样分层是为了**能在游戏外验证规则**: `tools/selftest.py` 把 `Core.cs` +
`selftest/SelfTest.cs` 单独编译成 `selftest.exe` (不引用任何 Unity 程序集), 跑 126 条用例 +
三本真词典的"C# 解析器 == 标准库 json"逐字节比对。改规则先跑它, 不用等进游戏看那一屏。

    python tools\selftest.py        # 报告写入 tools/acceptance/selftest_v<VER>.txt

新加任何规则时: 先写成 `Core.cs` 里的纯函数, 再在 `selftest/SelfTest.cs` 补用例。
`selftest/` 已被 csproj 的 `<Compile Remove>` 排除, 不会被编进插件 DLL。

## 构建 (无需安装 .NET SDK)
本机只装了 .NET 运行时、无 SDK。改用系统自带的 Framework C# 编译器 (C# 5) 直接编译:

    build.cmd                                   # 用脚本内的默认游戏目录
    build.cmd "E:\Games\Little Goody Two Shoes" # 显式指定游戏目录
    set LGTS_GAME=E:\Games\Little Goody Two Shoes && build.cmd

游戏目录按 **argv[1] → 环境变量 `LGTS_GAME` → 脚本内默认值** 的顺序解析;
缺 `LGTS.exe` / `LGTS_Data\Managed\` / `BepInEx\core\` 时直接报错退出 (exit code 1)。

产物: `build/LGTSChinese.dll` (v1.3.33 起编译 `Plugin.cs` + `Core.cs` 两个文件;
漏掉 `Core.cs` 会 CS0103)。
注: 源码已回退到 C# 5 语法 (无 nameof / 字符串内插), 以适配 in-box csc。
若日后装了 .NET SDK, 也可 `dotnet build -c Release` (见 LGTSChinese.csproj)。

**版本号只有一个来源**: `Core.cs` 里的 `internal const string VER` (v1.3.33 起;
此前在 `Plugin.cs`)。`Plugin.VER`、`[assembly: AssemblyVersion]` /
`[assembly: AssemblyFileVersion]`、DIAG 首行、自检报告都由它派生,
in-box csc 会把 assembly 特性写进 Win32 版本资源 —— 即"右键 DLL → 属性 → 详细信息"
看到的文件版本。因此改版本只需改 `Core.VER` 一处, 日志、BepInPlugin 元数据、
文件属性、自检报告不会漂移。
(历史问题: v1.3.23 及以前未声明 assembly 特性, 文件版本显示为 `0.0.0.0`。)

csc 每次编译会重新生成 ModuleVersionId, 所以**构建不是逐字节可复现的**;
对外比对请以发布包内 `SHA256SUMS.txt` 为准, 不要跨机器比 DLL 哈希。

## 部署结构
    <游戏>/BepInEx/plugins/LGTSChinese/
        LGTSChinese.dll
        translation/lgts_zh_by_refkey.json
        translation/lgts_display.json
        translation/lgts_item_names.json   (v1.3.18+, 79 键, 缺失自动降级)

改译文只需替换该 json 并重启游戏, 无需重编译。

## 与 AutoTranslator 并存 (当前采用)
本插件负责 **I2 数据层**文本 (对话/过场/事件等)。
同时保留 XUnity.AutoTranslator, 它负责两件本插件覆盖不到的事:
1. **CJK 字体回退** —— 已加载 `arialuni_sdf_u2019` 为 TMP 全局 fallback, 中文才不会显示成方块;
2. **非 I2 文本** —— 少量不走 I2 取词的 UGUI/TMP 文本, 由 AutoTranslator 的
   `_AutoGeneratedTranslations.txt` (24,700 条) + `UI_System.txt` (536 条) 兜底。
   **AT/XUAT 层为非权威兜底层**(v1.3.19 声明): 显示层词典 lgts_display.json
   优先命中, AT 值仅供 XUAT 兜底路径; display↔AT 存在历史实质差(89 条键只在 AT),
   不做批量同步, 仅逐条裁决后个别同步。

两者互不冲突: 插件在 I2 层就把结果换成中文, AutoTranslator 在其英文词典里查不到中文,
自然跳过; 反之非 I2 的英文才由 AutoTranslator 处理。

## 中文字体的三条通道
1. **AT 配置** (主通道): `AutoTranslatorConfig.ini` 的 `FallbackFontTextMeshPro=arialuni_sdf_u2019`,
   字体文件随包置于游戏根目录。
2. **可选字体包**: 插件目录 `font/lgts_cjk` (TMP_FontAsset 的 AssetBundle)。随包**不提供**,
   需要用 Unity 编辑器自行导出一个含 CJK 字形的 SDF 字体包; 插件发现则自动注入为 TMP fallback。
3. **运行时兜底** (v1.3.7 起, `TryOsTmpFallback`): 未找到 `font/lgts_cjk` 时, 用系统中文
   (Microsoft YaHei / SimHei / SimSun) 经 `Font.CreateDynamicFontFromOSFont` +
   `TMP_FontAsset.CreateFontAsset` 动态生成并注入 TMP 全局 fallback。
   因此在 AT 字体通道失效时一般也不会出现豆腐块, 只是字形风格与 arialuni 不同。

旧版 UGUI `Text` 组件另有一条独立兜底: 检出无 CJK 字形时按系统字体名替换 `font`,
并受 `AutoTranslatorConfig.ini` 的 `OverrideFont=Microsoft YaHei` 影响
(精简版 Windows 无雅黑时暂停菜单丝带可能空白, 见安装说明常见问题 2/3)。

## 如何确认生效
启动游戏后看 `BepInEx/LogOutput.log`, 应出现:

    [Info :LGTS Simplified Chinese] 已挂钩 System.String GetTranslation(...)
    [Info :LGTS Simplified Chinese] 已挂钩 Localize.OnLocalize 选择器护栏
    [Info :LGTS Simplified Chinese] DoLocalize 显示层挂钩: 4 个
    [Info :LGTS Simplified Chinese] LGTS 中文插件已加载, 词条 21189 条。

护栏: 每一处反射点 (`TypeByName` / `GetField` / `GetMethod`) 缺失都会打
`LogWarning` 或 `LogError` 具名回执; 取词方法一个都没挂上时会打
`LogError("未挂上任何取词方法")`。因此"钩子静默失效"在日志里是可查的。

逐条命中/未命中统计在 `BepInEx/plugins/LGTSChinese/DIAG.txt`:
退出游戏时写 `[FINAL] TMP seen=... fixed=... miss=...`。启动期写的是
`[HOST DESTROYED]` (计数接近 0 属正常, 见 v1.3.7 注释)。
