# 翻译工具链 (tools/)

这组脚本把「一份译本 CSV」变成「可发布的补丁」，并校验产物。
它们此前只存在于作者本地的批次工作区，v1.3.24 起随仓库分发，目的是让
**"三层词典如何同步、三类载体如何对齐" 这件事可以被复现和审计**。

## 数据流

```
docs/<译本>.csv                     ← 唯一的翻译来源 (记录键 / 英文原文 / 中文译文 / 修订译文)
        │
        ├─ apply_translation.py ──┬→ lgts_zh_by_refkey.json   按记录键直取
        │                         ├→ lgts_display.json        按 Norm(英文) 归一后匹配
        │                         └→ lgts_item_names.json     同上, 仅道具短名
        │
        └─ rebuild_at.py ──────────→ _AutoGeneratedTranslations.txt   精确→模糊→机械规范化

repack.py  ──→  LGTS-SimplifiedChinese-vX.Y.Z.zip + SHA256SUMS.txt
verify_release.py ──→ 验收报告 (退出码 0 = 全部通过)
```

四个载体口径必须**分列**统计，禁用合并数字：

| 载体 | 键数 | 角色 |
|---|---|---|
| `lgts_zh_by_refkey.json` | 21,189 | I2 取词主路径，权威 |
| `lgts_display.json` | 25,261 | TMP 渲染层，权威 |
| `lgts_item_names.json` | 79 | 道具弹窗专用，缺失自动降级 |
| `_AutoGeneratedTranslations.txt` | 24,700 | XUAT 兜底层，**非权威** |
| `UI_System.txt` | 536 (+9 行注释) | 系统 UI 静态词条 |

## 常用流程

### 换译本 / 应用新修订

```bash
python tools/apply_translation.py --csv "docs/xxx.csv" --live "D:\steam\steamapps\common\Little Goody Two Shoes"
python tools/rebuild_at.py        --csv "docs/xxx.csv" --live "D:\steam\steamapps\common\Little Goody Two Shoes"
```

两个脚本都会在写入前备份（默认后缀 `.bak_pre_apply` / `.bak_pre_rebuild`，
已存在则不覆盖），所以同一份 CSV 可以安全重跑。

### 打包与验收

```bash
python tools/repack.py --stage temp_work_result/dist/stage_v1324 --version 1.3.24
python tools/verify_release.py --stage temp_work_result/dist/stage_v1324 --version 1.3.24 \
       --live "D:\steam\steamapps\common\Little Goody Two Shoes" --csv "docs/xxx.csv"
```

`verify_release.py` 的 `--live` / `--csv` 可省略，省略时对应检查记为 SKIP。
字形检查需要 `UnityPy` + `numpy`，缺失同样记 SKIP 而非 FAIL。

## 关键约定

**为什么 display/AT 用 "Norm(英文)" 而不是 RefKey。**
RefKey 只在 I2 取词路径可用；Timeline 旁白、部分弹窗、UGUI 文本拿不到 RefKey，
只有英文原文。所以这两层以 `Norm(英文)`（去富文本标签 + 折叠空白）作键。

**为什么 display 更新时要 `pick()` 而不是直接覆盖。**
同一个英文串可能对应多条中文候选（同一句在不同上下文各译一次，标点或有差异）。
`pick()` 优先选与现有值"去标点后相同"的候选，从而只更新真正改动的措辞，
不会因为标点差异把整表措辞洗一遍。这是历次发布"改值数远小于候选数"的原因。

**为什么 AT 重建要转义换行。**
XUAT 按行解析 `_AutoGeneratedTranslations.txt`，值里出现真实换行会把一条拆成两条。
`esc()` 统一转成字面 `\n`（实际效果是游戏中换行，但文件仍是一行）。

**AT 为什么是非权威层。**
运行时 display 词典优先命中，AT 只在 XUAT 兜底路径生效。authoritative 数据是
by_refkey / display。因此 display 与 AT 允许存在历史实质差，不做批量同步，
只在逐条裁决后个别同步。

**构建不是逐字节可复现的。**
csc 每次编译会重新生成 ModuleVersionId。跨机器比对 DLL 哈希没有意义，
对外一致性以发布包内的 `SHA256SUMS.txt` 为准。

## 已知缺口

- **没有自动化测试。** `ParseFlatJson` 的畸形输入处理（孤立尾部反斜杠、不足 4 位的
  `\u`）在 v1.3.17 是手工验证的，仓库里没有对应用例。`verify_release.py` 校验的是
  **数据与产物**，不是 C# 逻辑。若要补，最划算的是把 `Norm` / `ParseFlatJson` /
  `TryNumTemplate` 这几个纯函数抽成可编译的断言程序 —— 但它们依赖
  `UnityEngine` 类型，不能简单地跑在无 Unity 的 CI 上。
- **没有 CI。** 编译需要游戏本体的 `LGTS_Data/Managed/*.dll`，属付费资产，不能进
  runner。这一步只能人工跑 `build.cmd`。
- `rebuild_at.py` 的"模糊"一级只在唯一解时采用；出现歧义会退回机械规范化。
  歧义条数没有单独报表，需要时可在脚本里加计数器。
