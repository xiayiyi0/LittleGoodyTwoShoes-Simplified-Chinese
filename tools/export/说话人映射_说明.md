# 说话人映射（导出说明，2026-11-14）

对应译者需求 `说话人映射_导出需求.md`。一次导出，长期可用；随批次更新。

## 这张表是什么、从哪来

游戏的对白资产（`data.unity3d` 里的 TextAsset，1,267 个）本身就带说话人和同场人物：

```json
{ "ID": "DLG_5_3_VSQ_04",
  "Participants": [ "Player", "Muffy" ],
  "Conversation": {
    "1": { "Author": "Player", "Text": "DLG_5_3_VSQ_04_001", "Next": [ 2 ] },
    "2": { "Author": "Muffy",  "Text": "DLG_5_3_VSQ_04_002", "Next": [ 3 ] } } }
```

节点的 `Text` **就是**游戏拿去 Gridly 取词的 recordID（也就是译本「记录键」），
`Author` 是这句话的说话人，文件头的 `Participants` 是同场人物。所以
「游戏显示键 K 那行时是谁在说」= `node(K).Author`——这层关系是资产自带的，
不依赖 Gridly/I2 两张表谁覆盖谁。反编译侧对应
`StorySystem.Models.Nodes.Node{Author,Text,DisplayName,Next}` 与
`StorySystem.Models.Intermediate.IntermediateConversation{ID,Participants,Conversation}`。

字段：`记录键 / 说话人ID / 说话人显示名 / 对话ID/节点ID / 上一行记录键 / 下一行记录键 /
同场人物 / 键的节点数 / 英文原文 / 备注`。一个键若被多个分支复用会有多行（289 个键如此），

`说话人ID` 是资产里的内部 ID（`Player`、`Rozenmarine`、`Bertha`…）。游戏里显示的
人名由译本自己决定，所以「说话人显示名」列只在本表能查到**裸名行**时才填，不硬编。

**这里有一条对译者有用的发现：现行版本的原文已经改过措辞，
`laddies` 那批争议句多数在现行表里已经不再是原句。** 例如：

- `XUAT_02190`「我还以为你们这些小子该在上课呢？」→ 现行 `DLG_6_2_VSQ_02_002`
  **"I thought you'd all be in class?"**（0.80，说话人 Player，同场 Player/Linda/Jakob）——
  原文自己把 `laddies` 改成了 `you'd all`，中文照现行句翻即可，不必再判「小子/孩子」。
- `XUAT_06355`「你真觉得在这儿养大你的小子们，会开心吗，吉多？」→ 现行
  `DLG_7_4_OLH_01_008` "…raise your **children** here, Guido?"（0.89，说话人 Fynn）。
- `XUAT_01731`「我倒真希望这个 Aziel 能把你们这群…」→ 现行 `DLG_4_5_WCR_C_01_006`
  "…this **Lady** would gobble you lot up…"（0.81，说话人 Player）。
- `XUAT_05171`「没错！咱们得让这女巫付出代价……！」→ 现行 `CUT_7_3_VSQ_01_013`
  "That's right — we need this **witch** to pay…"（0.77，说话人 Loreley）。

也就是说：`XUAT_` 行是 XUnity 在**更早的版本**抓下来的屏上英文，键号在现行表里已被重排/改写；
所以它们既没有对话节点，也和现行正文对不上号。**判这些行不如直接判它们对应的现行 DLG/CUT 行**——
登记表里那 30 行的「缺说话人」问题，真正需要回答的是现行行，不是 XUAT 行。

## 已知边界（别把这张表当全量真值）

1. **XUAT 行不是节点**：只能靠英文串反推。同文 1,102 行可信；近似 2,495 行必须人工确认；
   剩下的（约 3,441 行）现行表里没有对应句，说话人留空。
2. **非 XUAT 键里有 4,728 个没有节点**（21,189 − 16,461）：ITM/TUT/NARR/SUB/STG/TASK 全族 +
   部分 DLG/CUT（Timeline 直接播的行）。这些键空着就是「资产里没有」，没有用邻近行猜。
3. **同键多作者 9 个**：同一句被不同角色复用的场合，两行都在，备注列写明。
4. **I2 与 Gridly 同键不同文**：两边共有的 5,736 个 Dialogue 键里只有 1,033 个（18%）正文相同，
   个别对话整体错位（实测 `CUT_2_1_OLH_01`：I2 的 `_00N` 与 Gridly 的 `_00(N+1)` 同文）。
   所以本表**不用 I2 的键**，只在近似行里做交叉印证（一致写 `I2同键`，不一致写 `I2异键:…`）。
5. 说话人显示名只来自译本裸名行；`Player` 是游戏侧对玩家角色的叫法，备注里标"主角（伊莉丝）"。

## 复算

```bash
python tools/extract_textassets.py --out <dir>          # 一次, ~6 分钟, 只读游戏文件
python tools/speaker_export.py --assets <dir> --csv "docs/<译本>.csv" \
       --gridly <gridly_en_current.json> --i2 <i2_terms_en_current.json>
python tools/verify_speaker_export.py                   # 字段数/键归属/空说话人; 两次输出须逐字节一致
```

校验记录（2026-11-14）：三表字段数 10/8/8 全对、键 100% 在译本内、主表无空说话人、
重跑两次 sha256 一致。

## 一句话

`说话人` 列按需求导好了：对白主体 16,461 键直证，XUAT 另给 1,102 行同文 + 2,495 行近似。
登记表那 30 行里，3 行有直证、9 行有近似，其余 18 行是"现行版本已经没有这句"——
这类行不需要判，它们不会再上屏。
