## 二、逐条

### F1（原判 S）— 同英文多译文在 display 兜底路径无法区分

复核数字属实：**29 组 / 483 行 / 70 行与 display 值不同**。
但 70 行**全部是非 XUAT**，而非 XUAT 的 21,189 行**全部在 by_refkey** 里（`Gridly.GetStringData`
按 recordID 直取），这些行的专属译法本来就能上屏；29 组也**全部已由 `pick_overrides.txt` 钉死**
（`check_localization` G4.1–G4.3：未钉 0 / 悬空 0 / 陈旧 0）。

真正只能走 display 的是 XUAT 遗留行。`reachability.py --all` 实测折键遮蔽 6 条
（`XUAT_00496/00574/00578/00580/01281/01409`），属 PIPELINE 已记录的"47 行字面 `\n`"同一类，
不是新增缺陷。结论：**不改译文**；严重度下调为 L（已记录、已钉死）。

### F2（原判 M）— 钩子异常可观测性

属实：`HookErr < 20` 截断、`GridlyProbe_Postfix` 裸 `catch { }`、`PatchGridlyProbe` 成功日志
仍写"只观测, 不改输出"（实际会改写 `__result`）。但都在**已发布的 DLL**里，改动必须重编译、
重打 zip、重跑实机 DIAG。当前 v1.3.34 二进制已验证，**不为诊断性改动重发**。
已记入 `tools/PIPELINE.md`「待下个版本（要改 DLL）」：

- `HookErr` / `GridlyErr` 受限计数并写进 `[FINAL]` / `[GRIDLY SUMMARY]`（`err=N`）；
- 改掉"只观测"陈旧注释；
- G 组可据此断言 `err=0`。

补充：**Gridly 整条路径完全失效**其实已被现有 G 组抓住（`DIAG Gridly 精确取词已生效` 要求
`fixed > 0`），F2 剩下的风险只是"偶发单次异常无痕迹"。

### F3（原判 M）— "44 PASS" 被读成全绿

属实。已加 `--release`：

- 强制要求 `--live --csv --diag`，缺一即退出 1；
- 任一 SKIP 按"不可发布"返回 1（普通模式仍返回 2）；
- 普通运行在汇总后打印"本次不是发布模式"。

审查报告里的 `43 PASS / 0 FAIL / 1 SKIP` 是**审查环境缺 UnityPy** 导致；本机有 UnityPy 1.25.0。
修复前本机基线 44（51−7），修复后 46（53−7）。

### F4（原判 M）— 包完整性只查 6 个文件

属实，已修：

- `zip 文件集与发布树精确一致 (71)`：按 `repack.TOP` + BepInEx 全树构造应有文件集，与 zip 条目**双向**比对；
- `stage==zip 全部发布文件 (71)`：逐字节；
- `live==stage 运行树 (62, 不含 config)`：BepInEx 全树除 `BepInEx/config`（运行期会改写）+ 4 个运行时顶层文件；
- `SHA256SUMS 覆盖`：从 `need <= covered` 改为**精确相等**（含 zip 本体）。

没有把 live 的 README/LICENSE/changelog 纳入比对：live 是玩家安装目录，不是交付物；
"玩家装到的 == 验证过的"由 **zip==stage 全树**保证。

### F5（原判 M）— `--scratch` 实际要求旧文件在场

属实，已修：

- `apply_translation.py`：`backup()` 缺文件跳过；`item_names` 只要 `keys_item.txt` 在就重建；
- `rebuild_at.py`：`--scratch` 不再要求目标 AT 存在；
- 空目录实测：四本词典与 stage **逐字节相同**
  （`5d02d914…` / `5fe9ebf0…` / `7af1284d…` / `91522441…`）。

### F6（原判 M）— 文档把主路径写成 I2

属实，已修：`BUILDING.md`、`check_localization.py` 的 G1.3 标签、`pick_overrides.txt` 注释
统一为 **Gridly 精确主路径 + I2/TMP 兜底**。
